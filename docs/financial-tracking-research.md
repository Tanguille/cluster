# Self-Hosted Financial Tracking + Agent Integration Research

Research date: 2026-08-09. Goal: self-host a personal finance tracker covering crypto + stocks, with data reachable by Hermes/vmcp for LLM-driven recommendations.

## 3. Existing MCP servers pluggable into a toolhive/vmcp gateway

- **Firefly III MCP server** — [horsfallnathan/firefly-iii-mcp-server](https://github.com/horsfallnathan/firefly-iii-mcp-server), AGPL-3.0, last push 2025-08-09, 8 stars. Wraps Firefly III's REST API for Claude Desktop/Cursor-style MCP clients. Announced and endorsed by the Firefly III maintainer (JC5) in [github.com/orgs/firefly-iii/discussions/10396](https://github.com/orgs/firefly-iii/discussions/10396): built by a community member (Evans Mike / etnperlong) over a few days, tested against Gemini 2.5 Flash and GPT-4.1 Nano for interactive daily-budgeting chat queries. No scheduled/alerting mode mentioned — purely on-demand chat.
- **CoinGecko MCP servers** — see section 2. [cyanheads/coingecko-mcp-server](https://github.com/cyanheads/coingecko-mcp-server) is the most recently active (2026-07-30) and license-clean (Apache-2.0) option for crypto price lookups.
- **Alpha Vantage MCP server (official)** — [alphavantage/alpha_vantage_mcp](https://github.com/alphavantage/alpha_vantage_mcp), MIT, actively maintained by Alpha Vantage itself, for stock/forex/crypto/technical-indicator queries.
- **Octav Labs MCP server** — [Octav-Labs/octav-api-mcp](https://github.com/Octav-Labs/octav-api-mcp), MIT, active (2026-08-06), targets crypto portfolio tracking/DeFi analytics across 20+ chains — relevant only if on-chain wallet tracking (not exchange/CEX) matters.
- **No Ghostfolio-specific MCP server was found** in this search. Given Ghostfolio already exposes a documented REST API with bearer-token auth (see section 1), the lowest-effort path is a small custom MCP server that wraps Ghostfolio's existing `/api/v1/*` endpoints — same pattern as the Firefly III community server above, not a novel approach.
  **Superseded**: a later pass found [`mhajder/ghostfolio-mcp`](https://github.com/mhajder/ghostfolio-mcp), an existing maintained server — adopted instead of building a custom bridge; see [`docs/ghostfolio-financial-tracker-plan.md`](./ghostfolio-financial-tracker-plan.md).
- General registries checked: [github.com/modelcontextprotocol/servers](https://github.com/modelcontextprotocol/servers) (official reference/community list), [TensorBlock/awesome-mcp-servers finance--crypto.md](https://github.com/TensorBlock/awesome-mcp-servers/blob/main/docs/finance--crypto.md), [mcpservers.org finance category](https://mcpservers.org/category/finance) (220 servers listed, mostly trading/exchange-account tools rather than personal-portfolio-tracker wrappers).

## 4. Recommendation/analysis loop patterns

Direct evidence from the two most relevant communities:

- **Firefly III**: the maintainer-endorsed pattern (discussion #10396) is **on-demand chat** — a user asks an MCP-connected LLM (tested with Gemini 2.5 Flash / GPT-4.1 Nano) about their finances, the MCP server fetches live data from Firefly III's API in response to that specific query. No scheduled digest or webhook-triggered analysis was described.
- **Firefly III's own open feature request** ([issue #9753](https://github.com/firefly-iii/firefly-iii/issues/9753), still open) asks for exactly the chat-query pattern natively in-app: natural-language questions like "Why did my dining expenses increase last month?", self-hosted LLM support (Ollama/LocalAI) or optional cloud LLM, plus an "AI Suggestions" panel shown inline during transaction entry (i.e. a lightweight inline/contextual alert rather than a separate scheduled job). This confirms the community's demand is oriented around on-demand + inline suggestion, not a standing cron-based advisor.
- **Ghostfolio**: no AI/LLM feature discussion was found in this search (issue tracker is bugs-only; feature talk lives in Discussions/Slack, which weren't directly searchable here) — this is an absence of evidence, not evidence that nobody has proposed it.

**Bottom line on section 4:** the concrete precedent from Firefly III's ecosystem is a thin MCP wrapper over the app's existing REST API, queried on-demand by chat — no example of a scheduled "cron job asks the LLM to review the portfolio and post an alert" pattern was found in either project's public discussion. Building the scheduled/alerting variant on top of Hermes would be net-new work relative to what these projects have documented, not a pattern to copy — though it fits naturally on top of a working on-demand MCP integration (same server, cron-triggered `call_tool` invocation instead of a live chat message).

## Recommendation

1. **Ghostfolio** is the strongest fit among actively-maintained apps in this survey that natively track both crypto and stocks with automatic price sync (Yahoo Finance backend) and a documented bearer-token REST API — Sure (below) matches on features but had no Helm chart or MCP precedent at research time. No existing Ghostfolio MCP server was found at the time of this research, so a small custom wrapper was the plan.
   **Superseded — actual deployment**: `mhajder/ghostfolio-mcp` (an existing maintained MCP server, found later) was adopted instead of a custom wrapper, and the app is deployed via `app-template` on the cluster's shared CNPG Postgres + Dragonfly Redis, not the third-party `ByTheHugo/ghostfolio-helm` chart (which bundles its own Postgres/Redis subcharts, duplicating the shared-cluster convention). See [`docs/ghostfolio-financial-tracker-plan.md`](./ghostfolio-financial-tracker-plan.md) for the deployed shape.
2. Pair it with the **official Alpha Vantage MCP server** (stocks) and **cyanheads/coingecko-mcp-server** (crypto) if you want live market context beyond what Ghostfolio already caches — both are actively maintained, permissively licensed, and drop straight into a toolhive-style gateway alongside your custom Ghostfolio tool.
3. **Sure** (the maintained Maybe Finance fork) is the fallback if Ghostfolio's data model doesn't fit — same crypto+stock coverage, same AGPL license, most active repo in the whole survey (pushed 2026-08-09) — but has no Helm chart or MCP server precedent yet, so it's more integration work up front.
4. Skip Firefly III and GnuCash for the *portfolio* half of this task: Firefly III has no investment/crypto tracking (open, unresolved feature requests), and GnuCash's self-hostable web/API layer is stale (>1 year no commits on both `gnucash-web` and `gnucash-rest`). Firefly III's MCP server and AI feature-request thread are still worth reading as the closest documented precedent for the recommendation-loop UX, even though the app itself isn't the tracker to use here.
