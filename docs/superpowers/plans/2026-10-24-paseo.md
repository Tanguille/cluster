# Paseo community-image implementation plan

Approved revision: 2026-10-25. [Design](../specs/2026-10-24-paseo-design.md).
Supersedes the custom image/four-agent packaging plan; single-PVC layout stays.

1. Move safe seed/config/password guard into app ConfigMap resources. Preserve
   create-only behavior, public main-branch repositories, mutable config and
   manual private clone. Disable deferred Claude/Codex; use absolute Hermes
   ACP command under persisted HOME. Do not require Hermes to start the pod.
2. Pin the approved community image for all containers. Explicit tini/guard
   command must override image CMD and call upstream entrypoint without args,
   avoiding community paseo-start and LiteLLM/config overwrites. Mount scripts
   and defaults read-only; protect shell expansions from Flux substitution.
3. Remove custom Docker sources, publication workflow and old smoke harness.
   Remove image-tag substitutions/publication gates; preserve 70Gi storage,
   kopiur, internal route, required Secret, gVisor and detached namespace.
4. Document official manual Hermes installer download from pinned commit,
   inspection, non-interactive install into HOME, ACP check, interactive setup
   and persistence/egress limitations. Retain gh login and guarded rsume clone.
5. Focused shellcheck/shfmt and Kustomize/integrated flate checks; inspect
   rendered command, mounts, Secret and unique PVC/backup graph. If space
   permits, pull community image and test fresh UID1000 startup without
   LiteLLM, versions and password guard. No custom build or shared pruning.
   Old custom-image smoke is not evidence for this image.
6. Record exact evidence/limits in community-image-report.md. Parent handles
   independent review/full suite. No commits/push/SOPS/live operations here.
   Deployment, real password and live auth/persistence/backup acceptance remain
   separate approval gates. Preserve PVC on rollback.
