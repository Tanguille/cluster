# Paseo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an internally accessible, password-protected Paseo with four preinstalled agents and durable working state, without touching sibling deployments.

**Architecture:** One app-template workload in `ai`, backed by separate home and workspace kopiur PVCs. A GitHub Actions-built immutable image supplies all executables; initialization seeds only absent public checkouts and config. Secret and image availability gate GitOps activation.

**Tech Stack:** Flux, bjw-s app-template, Gateway API, Ceph/kopiur, Docker/Buildx, GitHub Actions, npm, Hermes PM/Python, Bash.

**Spec:** [Approved design](../specs/2026-10-24-paseo-design.md).

## Global Constraints

- Existing OpenCode and Hermes deployments remain untouched.
- Use `ai`, internal `paseo.${SECRET_DOMAIN}`, port 6767; explicitly disable relay.
- Use the design's exact versions and immutable integrity pins; never production `main`/`latest` or curl-to-shell installers.
- Agent binaries and Python runtime must live outside persistent `/home/paseo`.
- Seed only absent public repositories, both `main`; private rsume `master` waits for interactive gh login.
- No fabricated secrets, host credentials, host/socket mounts or Kubernetes privileges.
- SOPS, push/publication and live activation require separate permission; do not activate before image and password exist.
- All shell scripts use `set -euo pipefail` and pass shellcheck. No YAML-specific test framework.

## Review Focus

1. Mounted empty HOME hides bundled dependencies: Task 1 checks all binaries and ACP with real empty mounts.
2. Interrupted clone or an existing dirty directory loses work: Task 1 exercises failed clones, reruns, dirty repos, plain directories and dangling symlinks.
3. Public UI/health gives false confidence in password protection: Task 1 tests actual control authentication, not just HTTP 200.
4. Missing password or changed runtime UID starts an unsafe daemon: Tasks 1–2 check fail-closed startup and rendered non-root/token settings.
5. Authentication works once but disappears on reschedule: Task 2 checks persistent paths offline and records a permission-gated restart/login check.

## Task 1: Build and prove the preinstalled runtime

**References:** Design image contract; existing Talos image/workflow and Docker
Lint workflow. Do not modify those precedents or weaken shared lint policy.

**Interfaces:** Produces `ghcr.io/tanguille/paseo:sha-<full-commit>@sha256:<actual-digest>`;
UID/GID 1000; `/usr/local/bin/paseo-seed` init command; default daemon entrypoint;
`/home/paseo` and `/workspace` mount contract. Seed accepts no repository/user
input: it uses exactly the two public URLs/branches from the spec. Smoke script
accepts one local image reference, exits nonzero on any failed assertion.

- [ ] Resolve the `0.13.0` base digest and verify the gh archive checksum;
  commit real pins in Dockerfile, and generate npm lock data for the exact
  three package versions. Record Hermes commit and archive integrity. Confirm
  base architecture, upstream entrypoint and all resolved executable paths.
- [ ] Write `scripts/paseo-smoke.sh` assertions before image implementation;
  run it against the unextended base and record expected failures for absent
  agent binaries/seed command/fail-closed guard. Keep this one direct smoke
  script rather than adding a test framework.
- [ ] Implement the child image: pinned npm packages installed under
  `/usr/local` using the committed lock, pinned gh archive, Hermes source under
  `/opt/hermes`. Use its own PM lock to provision Python/PM and build the frozen
  sealed ACP environment as described in the spec. Link the installed Hermes
  launcher into PATH without changing Paseo's Node. Verify SQLite >=3.51.3 and
  source/venv access as UID 1000; stop for review if the combined base cannot
  meet this without a material design change. Do not add full Hermes s6,
  desktop or messaging services.
- [ ] Add the wrapper under upstream `tini`: reject empty password, then exec
  upstream `paseo-docker-entrypoint` without replacing its supervisor command.
  Add version-1 default config with the exact Hermes ACP provider tuple.
- [ ] Implement `seed.sh`: create writable config directories, copy default
  config only if absent, skip every existing destination (`-e` or `-L`),
  clone public `main` into a unique same-filesystem temp sibling with
  `GIT_TERMINAL_PROMPT=0`, check absence again and rename on success. Trap
  cleanup of only its own temporary path. No rsume, pull/reset, overwrite,
  credentials or root chown at runtime.
- [ ] Complete image smoke checks with temporary disposable mounts owned by
  1000:1000 and the real container entrypoint. Check `opencode --version`,
  `claude --version`, `codex --version`, `gh --version`, `hermes --help`;
  prove each executable resolves outside HOME. Send bounded JSON-RPC ACP
  `initialize` to `hermes acp` and require the matching successful response,
  not just a surviving process or import. Run with external networking disabled
  for this startup check to expose lazy install dependencies. Distinguish this
  protocol check from authenticated inference, which is deferred.
- [ ] Exercise seeding against temporary local Git remotes via a PATH-scoped
  Git wrapper in the smoke script (map only the two approved URLs). First run
  produces correct main checkouts; second run preserves hashes and dirty/
  untracked files. Also preserve plain directories, dangling symlinks, and
  existing config. Simulate a failed clone, verify no final partial checkout,
  then retry successfully. Assert rsume never appears. Do not replace the
  implementation's real production URLs with test URLs.
- [ ] Start daemon with an ephemeral generated test password, relay disabled
  and the allowed host. Require health 200, non-root daemon process, rejection
  of missing/wrong control credentials and successful authenticated CLI/API
  control. Use the pinned Paseo client's documented authentication path;
  do not assume HTTP Basic. Check disallowed Host rejection. Missing/empty
  password must exit nonzero before listening. Never log the test password.
- [ ] Run `mise exec -- shellcheck docker/paseo/*.sh scripts/paseo-smoke.sh`,
  `mise exec -- hadolint docker/paseo/Dockerfile`,
  `docker build --platform linux/amd64 -t paseo:check docker/paseo`, and
  `bash scripts/paseo-smoke.sh paseo:check`. All assertions must pass; capture
  versions, exit codes and ACP result without auth material in README evidence.
- [ ] Add `.github/workflows/paseo.yaml`: path-filtered PR and main builds plus
  dispatch, SHA-pinned actions matching peer conventions, checkout credentials
  disabled, concurrency and bounded timeout. PR job uses `contents: read` only;
  trusted publication job alone receives `packages: write`, never
  `pull_request_target`. Build/load, run the same smoke checks, then publish
  that tested image under source SHA (no latest). Emit digest/provenance.
  Verify untrusted PRs cannot publish. Check workflow syntax with the repository
  workflow checks and locally available actionlint; record any unavailable tool.
- [ ] Review lane 1; publication remains blocked until permission is given.
  Record the real published digest and successful unauthenticated image pull
  if package visibility is public. If private, stop for an approved pull-secret
  approach instead of reusing unrelated credentials. Use a conventional commit
  only if implementation-session instructions permit; never push implicitly.

## Task 2: Wire GitOps, persistence and operator handoff

**Interfaces:** Consumes Task 1's tested digest and init command. Produces
`paseo-home`, `paseo-workspace`, `paseo` Flux Kustomizations; two claims; one
non-root single-replica workload; internal route; required Secret key contract.

- [ ] Read add-app, kopiur and scoped review guidance at implementation time.
  Create three Flux Kustomizations in `ks.yaml`. Home/workspace use
  `../../../../components/kopiur` with `APP=paseo-home`/`paseo-workspace`,
  `PVC_CAPACITY=20Gi`/`50Gi`, `KOPIUR_PUID=1000`, `KOPIUR_PGID=1000` and the
  design's exclusions. The app depends on both. Storage directories contain
  standard empty-resource Kustomization roots; reuse components, not copied CRs.
- [ ] Create the app-template HelmRelease against existing `app-template`
  OCIRepository. Use Task 1's exact digest, `Recreate`, one replica, matching
  init image running `/usr/local/bin/paseo-seed`, shared home/workspace mounts,
  and all environment/security/resource/probe settings from the design.
  Disable service-account automount; no RBAC. Add only the internal HTTPRoute
  to `envoy-internal` and service 6767. Password is a non-optional secretKeyRef,
  not postBuild plaintext. Keep the namespace resource list unchanged for now.
- [ ] Render the detached app with `mise exec -- kustomize build
  kubernetes/apps/ai/paseo/app` and the namespace root. For integrated checks,
  temporarily wire the new ks in a disposable validation copy and run
  `mise exec -- flate test all -p <validation-copy>`; this is necessary while
  activation is gated because unreachable ks files may not be discovered.
  No secret decryption or dummy credential is needed to validate secretKeyRef.
  Inspect Helm-rendered Deployment/Service/HTTPRoute and both sets of storage
  CRs: correct names, sizes, ownership, mounts, backup schedules, dependsOn,
  digest, probes, route and security settings. Reject duplicate PVCs or backup
  names. Plain Kustomize success alone is not Helm validation.
- [ ] Write `docs/paseo.md` with exact discovery/exec commands for the rendered
  workload, non-root `id` check, `gh auth login --hostname github.com
  --git-protocol https --web`, `gh auth setup-git`, and `gh auth status`.
  Document token persistence/keyring limitations without printing credentials.
  After login, test `/workspace/rsume` absence (including dangling symlinks),
  then `gh repo clone Tanguille/rsume /workspace/rsume -- --branch master`.
  Existing destinations are left alone. Include provider interactive setup,
  direct internal HTTPS connection, no relay, default-config merge behavior,
  upgrades and PVC-preserving rollback from the design.
- [ ] Record pending activation gates in that runbook: tested published digest
  pullable; permission for SOPS and a human-provided real password; include
  encrypted `secret.sops.yaml` in app resources only after approval; separate
  approval for push and deployment. Only then add `./paseo/ks.yaml` to the ai
  root. If approval is unavailable, leave the change explicitly inactive and
  do not present deployment as complete.
- [ ] Run `mise exec -- bash .agents/skills/pr-review/scripts/validate-pr.sh`
  on the final reachable tree, plus `git diff --check`; verify flate actually
  ran and did not silently fall back to Kustomize. Review scope to confirm no
  sibling app/shared policy edits, credentials or unsafe mounts. Record command
  outcomes and any pre-existing unrelated failures separately.
- [ ] Hand off live acceptance, not automatic execution: after deployment
  permission, verify Flux readiness, gVisor startup, internal TLS and WebSocket
  password rejection/success; authenticate each provider and run one benign
  session in the intended checkout. With separate restart approval, confirm
  auth/config/dirty workspace survive restart and no public/private repo was
  overwritten. Check both SnapshotPolicies/Schedules and successful snapshots;
  never claim restore works without a separately approved restore exercise.
- [ ] Final review and permitted conventional commit(s); request push/deploy
  approval separately. Roll back image/config in Git, keep all storage ks/PVCs
  and backups. Never remove the namespace entry as a casual rollback because
  Flux prune could delete persistent resources.

## Verification budget and checklist

| Claim | Owner | Minimum evidence | Limitation |
| --- | --- | --- | --- |
| Executables/ACP survive HOME mounts | Lane 1 | One offline mounted image smoke run | Not provider inference/gVisor |
| No workspace/config overwrite | Lane 1 | Seed fixtures including failure/rerun | GitHub availability separate |
| Control is password protected | Lane 1 | Actual negative/positive control handshake | Live proxy needs acceptance |
| Correct GitOps/storage/security graph | Lane 2 | One integrated flate render plus scoped review | Not live CSI restore |
| Durable authenticated use | Operator, Lane 2 runbook | Approved live sessions/restart/backup status | Restore separately authorized |

The smoke script is the sole durable verification affordance; fixtures are
temporary and cleaned. Reuse image evidence only for the identical digest;
repeat affected checks after changing entrypoint, dependencies or seed logic.
If local Docker is unavailable, use the non-publishing CI build and record that
limitation; never replace runtime evidence with a Dockerfile review.
